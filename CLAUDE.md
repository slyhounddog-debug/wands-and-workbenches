# Wands & Workbenches — notes for future sessions

A **2-player local co-op browser game** on a vertical split screen. Left: a tiny **Builder** runs an isometric elemental factory on shiny reflective grass. Right: a tiny **Wizard** explores a 200×200 isometric wilderness with **no attack of his own** — every spell, potion, shield potion and garment is made in the factory and sent through the **Spell Portal**. A second **Skill Portal** banks element packets, spells and Aether Shards as skill-tree currency. **8-bit pixel-art** look throughout. One shared keyboard+mouse or two gamepads. No solo mode, no online.

The original design doc was "Complete Game Spec v5.0" (pasted by the user, not stored in the repo). The game has since been deliberately reworked well beyond it — see **Design direction & deviations** below. When this file and the old spec disagree, **this file wins**.

## Running & testing

- Plain HTML/CSS/JS, **no build step, no npm dependencies**. Open `index.html` directly — it must keep working over `file://` (no ES modules, no `fetch` of local files; fonts and audio are local files under `fonts/` and `audio/`).
- Debug/test hook: `window.__wands` → `{ G, Main, FA, WZ, UI, R, CFG, DevBot, menu (= `Menu`, the front door), start(slot), deliver(kind), bank(kind, n), step(dt, n), boss(), event(n), egg(kind), bot(who), Snap, snapshot(), snapView(mode) }`. `event(n)` forces event n (1-6 = the first cycle, 7 = Cycle 2's Migration...) to start in 5 seconds; `egg(kind)` delivers an Egg. `step` runs the simulation with zeroed inputs (skipped while `G.paused`, e.g. on the victory screen); with the dev bot on it plays the Wizard through the real pad path instead. `bot('wizard')` / `bot(null)` toggles the **dev Wizard bot** (see below). In game, **F3** or **`** toggles the debug overlay (XP/min, packets/min, bank rates, portal rates, ETA to the next affordable skill). **F2** with the overlay open, the SNAPSHOT bar under it, or `__wands.snapshot()` runs the dev-only **snapshot photo test** (see **Architecture guardrails**).
- Headless playtests: Playwright is **not** installed in the repo. Past sessions installed `playwright-core` into the session scratchpad and launched the system Edge (`chromium.launch({ channel: 'msedge', headless: true })`). Use a recent playwright-core (1.56 worked; 1.47 fails to launch current Edge). The real rAF loop keeps simulating between your `step` calls, and the camera eases, so wait ~1s before screenshots after teleporting the Wizard. Hide the controls card first (`UI.help(false); G.helpT = 0`). Load `file:///C:/Games/Wands&Workbenches/index.html`, wait for `#loadMsg.ready`, click (starts the studio intro), press a key (skips it), click `#mNew` then the first `#menuSlots button.slot`, then drive the game through `window.__wands`. Collect `pageerror` + console errors and take screenshots (1280×720 is fine — the stage scales to fit).
- `node --check js/*.js` is a quick syntax gate. **Acceptance checks on every build**: the syntax gate, a headless playthrough with no page errors, the **front door run** (`node tools/menucheck/run.js`, see **The living menu**), and the **snapshot photo test** (`node tools/snapcheck/run.js`, see **Architecture guardrails**) with no FAIL. Headless pitfall: the boot screen's key / click listener is still armed until the studio intro has been started and skipped, so a test that calls `__wands.start()` straight away freezes on its first key press; go through click -> Space -> wait for `!StudioIntro.isActive()` first. A headless page may also have blurred, which opens the pause menu (`Main.pause(false)`).
- **Dev tool**: `node tools/devtool/server.mjs` (port 8090, `PORT=` for a test copy; `tools/devtool/start.cmd` double-click) = Layout / Variables / Formulas / Audio tabs over a seeded, muted preview of the game. Full docs: `tools/devtool/README.md`. It only ever writes `overrides/`; keep those files **empty** in commits unless the user made the edits on purpose (test runs must clean up: POST an empty model / `{values:{}}` and DELETE test clips through the API). Run test copies on another port and never kill the user's own tool server.

## Readability pass (2026-10-26)

- **Spell items are pictures**: `it_<spell>` for the 10 combos + the Nova are hand-drawn pixel maps in sprites.js (`S` in the "combo spell items" task), each meshed from its elements' shapes (flamethrower = wind ring + flame, tempest = drop in a ring, steam = a spiked half-fire half-water mine, sandstorm = boomerang, magma = cracked lava rock, mud = a blue and a brown orb, meteor = rock in a flame tail, thunder = cloud + bolt + rain, blizzard = snowflake with a pebble heart, geyser = rocky vent with a water column, nova = all four round a white heart). They show in the tree costs, bank, belts and hands: a new spell needs a map there.
- **Armor is a faint bubble** round the Wizard (`R.drawShield`: a pixel-stepped ellipse with a slow shimmer, brighter with more armor, flickers under 20%); the old heater-shield object is gone.
- **Blueprints show their needs** as chips (`R.needChips`: material icon + have/need, green when that material is paid) above the blueprint; the faint item piles are gone.
- **Skill tree branch order** (`CFG.branches`): BUILDER left, BUILDINGS middle, WIZARD right.
- **Picking in the menu world is the game's pick button**: `pickTick` (menu.js) runs the same press buffer (`CFG.inputBuffer`) and hold-to-repeat as `Main.controls`; `pickFocus` sets `R.focus` each step like `Main.updateFocus` (the mouse's hovered thing, else `FA.findTarget('pick')`), so a loose spell hops with its ring and a belt spell lifts inside a gold tile ring (`R.drawBeltItem`, menu only) plus the key prompt (`Menu.hints`).
- **Menu world fog**: `Menu.drawEdge` (fog outside the patch + the rim + outline) is drawn after the scenery and before the plates, so the portal, characters, spells and effects are never dimmed. Spells riding the belts are drawn in a pass of their own over every belt (`R.drawBeltItem`, `R.drawBelt(..., noItem)`), floor / flying items sit over the belts too, and in the menu world `FA.candidates` is generous (belts within 2 tiles, reach 2.4; floor items 2.2).

## Architecture guardrails (online co-op roadmap)

Online co-op will be added later, **host-authoritative**: one machine runs the full sim, the guest sends pad input (through the same `IN` seam the dev bot uses) and renders state snapshots of `G`. It is **not being built now** (no networking code, no net.js). Gameplay comes first, but every system built from now on must keep that build cheap. Follow these in ALL future work:

1. **All gameplay state lives in `G`, as plain serializable data.** No functions, DOM nodes, canvas objects, class instances with methods, or closures stored in game state. If it affects what a player sees or what happens next, it is in `G` and it survives `JSON.parse(JSON.stringify(G))`.
2. **All input flows through `IN`.** Nothing reads keyboards / pads directly outside the input module (the dev bot and the future network guest both depend on this seam).
3. **Render code reads state; it never mutates it and never keeps private state that changes what's drawn.** Anything on screen must be derivable from `G` alone, every frame. No hidden caches a snapshot couldn't reproduce.
4. **Sim randomness and time come from the game's seeded RNG and clock** — not `Math.random()` / `Date.now()` sprinkled through gameplay logic. (Rendering-only sparkle may use them; simulation may not.)
5. **New systems must be snapshot-safe.** If a feature can't be expressed within rules 1-4, stop and flag it to Josh rather than working around the rules. A flagged exception is a conversation, not a silent shortcut.
6. **Saves stay self-describing.** New persisted fields go through the existing save format + `QUEST_VERSION` migration path — the future online build reuses that serialization to sync a guest.

**Standing check — run it on every future build:** *snapshot photo test passes (no leak warnings, frames match).* Run `node tools/snapcheck/run.js` (or `__wands.snapshot()` in a playthrough and read `__wands.Snap.report`). The verdict is PASS (nothing found), KNOWN (only entries in `Snap.KNOWN`, the baseline of the 2026-10-22 audit) or FAIL (a new leak, a new state issue, or any pixel difference). Never ship a FAIL; if you fix a baseline entry delete it from `Snap.KNOWN`; if a new entry is unavoidable, flag it (rule 5) instead of adding it quietly.

The photo test (`js/snapshot.js`, dev-only, listed in the Controls page DEBUG section): capture walks `G` into a plain JSON snapshot and lists what could not survive (functions, DOM / instances, cycles, NaN, shared references); the photo draws one live frame, swaps the global `G` for a read-only proxy of the snapshot and draws it again with the real renderers while every other module's live state (`R.*`, `UI.*`, `WZ.*`, `Main.*`, `IN.*`...) is a trip wire. A leak is a read of a field the snapshot lost, a write to `G` by a renderer, or a read / write of live state outside `G`; each logs `[snapshot] LEAK ...` to the console and the read still returns the live value so the frames can be compared pixel for pixel (Math.random and the clocks are pinned for both). The snapshot format is its own thing; the save format is untouched. Not covered: the DOM HUD (only the canvas frame is redrawn) and static things regenerated from the world seed (terrain, palette, landmark positions: `ALLOW` in snapshot.js).

## The living menu (2026-10-26): the front flow is a world, every menu a set of floor plates

After the loading screen and the studio intro (both unchanged) the game opens on a small isometric patch of the REAL wilds (the Wizard's terrain, grass and renderer) with both characters standing in it: the only place where the Builder and the Wizard share a world. **No DOM menus exist in the front flow** (`#menu`, `#players`, `UI.menuPage / howPage / slotPage / buildMenu`, `Players.open / render / tick`, `UI.onlinePage / hostSlots / hostLobby / joinPage` and their CSS were deleted). What is still DOM: the loading bar, the error badge, and everything in-game (HUD, pause menu, results, the disconnect banners). Code: `js/menu.js` (state + logic), `js/menudraw.js` (drawing), hooks in `R.drawWorld` / `R.drawFactory`, `Main` and `WZ`.

- **The menu world is a scratch game state.** `Menu.make()` builds a `G` with the game's own `blankState` / `WZ.fresh` / `FA.fresh` plus `G.menu` (plain data: plates, windows, countdown, sequence, toasts, an event ring). It is never saved, never touches a save (`Main.save` is not called from it; `slot` is 0) and `Main.toTitle` replaces it with a fresh one. The Wizard is the real `G.w` (the start of the world, a dry patch of it), the Builder the real `G.bd` on a small scratch factory floor laid over the same patch (factory tile `(fx, fy)` = world tile `(fx + Menu.OX, fy + Menu.OY)`; `Menu.view(v)` is the wilds' view shifted by that, so every factory drawing function runs unchanged). The spell belt line is 8 real belts moved by `FA.update`; the Builder picks a spell off it (left click / A, walk-and-pick with the mouse) and throws it (right click / B) at the Spell Portal: `FA.land` → `FA.deliver` → `WZ.send` → `WZ.incoming` → `WZ.cast`, the real spells with their drop-ins, knockback and shake. **He can also throw a spell at the Wizard**: in the menu world the Wizard is a receiver (`FA.menuWiz`, `'wiz'` in `FA.throwList` / `throwTarget` / `accepts`, outlined by `R.outlineObj`), and a spell that comes down within one tile of him (`Menu.catchSpell`, called first in `FA.land`) fires on him through `WZ.incoming` (the drop-in lead-up, the toast, no damage) without the Spell Portal's suck / arc flight; the Wizard picks nothing up (a spell thrown further off just lies on the floor); `Menu.spellName` toasts the name (a window on the canvas). `G.menu` switches off only the wild monsters (`WZ.update` spawn), the damage (`WZ.damage` returns) and the HUD; the camera is fixed on the page's centre (`Menu.camOf`: the main sets' patch is centred across the screen and sits low, `SHIFT_MAIN` = [0, 150], so the sky above its top-right edge is free for the windows) instead of following the Wizard, and `FA.portalCells` has no Skill Portal. The menu's patch has no trees, rocks, dig spots, shrubs, cracked rock or boulders on it (`Menu.cleared`: marked broken in the scratch `G.w` / skipped by the renderer) and the **plates are drawn over all the scenery** (`MENU_TOP` in `R.drawWorld`: scenery, then the plates, then everything that stands or moves: characters, belts, props). Boot is ~0.5 ms: the world paints on the first frame.
- **The patch** (`RECT_MAIN` / `RECT_CS` in menu.js): the start of the wilds is the tip of a landmass (water south, east and south-west), so the main menu's floor is the dry square round the spawn and the character select's (`RECT_CS`, 32 x 19 tiles) grows west and north over the dry land there (the rectangle, the camera and the Builder's floor ease there with the page; `Menu.setLand` marks the dry tiles). **The spell belt line and the Spell Portal are at the left**: 8 belts run down the patch's left edge (`BELT`: x 95.5, pointing south) and end two tiles short of the Spell Portal (`PORTAL`), so nothing slips in by itself: the Builder picks a spell off the end and throws it. The characters start at `START` (the Builder by the belt's end, the Wizard low in the patch). Outside it the world is dimmed; a dirt rim hangs under the near edges. Characters are kept inside (`WZ.slide` already keeps the Wizard out of water).

## Online co-op (Phase 1, 2026-10-25)

Host-authoritative, one room code. **Host = the Builder** (runs the whole sim exactly as offline), **guest = the Wizard** (never simulates: sends a pad, draws snapshots). Offline local split-screen is untouched (verified frame- and state-identical to the previous build with a pinned-random run).

- **Transport** (`js/net.js`): PeerJS cloud for signaling only, a reliable ordered WebRTC data channel for everything small (hello, pad, buy, ping, toasts) PLUS (since `Net.VERSION` 3, 2026-10-26) a second **unreliable, unordered snapshot channel** (below), **STUN only** (PeerJS's default config adds a free TURN relay: it is overridden on purpose; a relay is Josh's decision). The peer id is `ww-<CODE>` (6 chars of `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, regenerated if taken). The room locks to the first guest's random token (kept in sessionStorage): the SAME guest can rejoin, anyone else is refused. `Net.VERSION` (bump on ANY wire change) is checked in the handshake; the welcome also carries the wilds' seed and a terrain fingerprint, so a different build says "game version differs" instead of crashing.
- **Snapshot channel** (`snapChannel` / `snapOut` / `snapIn` in net.js): a reliable channel made the guest's picture arrive late in bursts on a lossy link (one lost packet holds back everything behind it until it is resent; a stale snapshot is worth nothing). Both sides open a second RTCDataChannel on the same connection with the same **negotiated id 5** (PeerJS never sees it; no renegotiation), `ordered: false, maxPacketLifeTime: 500` ms (`LIFE`: it must be several ROUND TRIPS; at 150 ms on a 145 ms relay path the first lost packet of a ~10 packet snapshot could never be resent and the guest saw 5-20 pictures a second). Snapshots are also sent with numbers cut to 3 decimals (`SHORT` in sendSnap: 11 KB -> 5.7 KB deflated). The guest's pause menu shows pictures/s, loss % (gaps in `n`) and its draw fps; `Net.simLoss` (0-1, per packet) loses snapshots on purpose for tests. A snapshot goes out as `[4 byte n][deflated bytes]`; the guest drops any with `n <= Net.lastN`. Snapshots over `SNAP_BIG` (60 KB), or a channel that is not open, use the reliable `snap` message as before. `Net.BACKLOG` counts both channels. `?lossy=0` on BOTH computers turns it off (the A/B test). The pause menu's room line shows `lossy` / `reliable` (`Net.stats.chan`). `LOSSY0=1 node tools/nettest/run.js` runs the fallback.
- **Wire** (`Net.VERSION` 3 now; the lines below are the version 2 description: the pad carries the right stick `rx` / `ry`): guest -> host `hello`, `pad` (30 Hz, the `IN.pad` shape; presses latched between sends into the edge fields, held state in every packet), `buy` (tree purchase intent), `ping`, `bye`. Host -> guest `welcome`, `refuse`, `snap` (20 Hz: `Snap.wire()` = `JSON.stringify(G)`, deflated with CompressionStream, ~50-100 KB raw -> 6-13 KB sent in a mid-game factory), `toast` (the Wizard's toasts), `buyres`, `pong`, `bye`. Every snapshot is a full one (no deltas yet). Snapshots are skipped while the data channel's buffer is backed up. `Snap.wire` equals `Snap.capture().G` (checked by tools/nettest): it is the native serializer instead of capture's audit walk because it runs 20 times a second.
- **Flow** (since the living menu): Online plate > Create plate > a slot plate opens the room and a window above the Create plate shows the code; the host waits in the menu world. The guest walks to the keyboard prop (Online > Join), presses E and types the code with the real keyboard (Enter joins, Backspace edits, E / Esc cancels). When the guest says hello (`Net.hooks.guestJoined` -> `Menu.guestJoined`) both are in the **character select** in the host's menu world, and the game starts when both are ready (`Main.launch` with `Players.ctl = { kbB: true, kbW: false, pb: real pad ? 0 : -1, pw: 1 }`, `Net.on = true`): the roles are fixed (host = Builder, guest = Wizard; the statues are decorative). **The lobby needs no wire change**: the host's menu world is a game state like any other (`G.menu` is plain data), the host streams it as snapshots, the guest's pad (already sent) walks the Wizard in it (`Net.drive` writes it into `IN.pad[G.ctl.pw]`), and the guest draws it with `Menu.guestFrame`; when the host's real game state arrives the guest's `Main.enterGuest` takes over as before. Things only one machine can know are reactions to events in `G.menu.ev` (see **The living menu**). **Room codes have no E** (`Net.ALPHA`: E is the keyboard prop's cancel key; 0 O 1 I L stay out). There is no solo mode: the host waits in the lobby.
- **Input bridge**: `Net.drive()` (after `IN.pollPads`, the dev bot's seam) writes the guest's pad into `IN.pad[G.ctl.pw]`; the guest's `y` and `startHeld` are dropped there (T opens the guest's OWN tree; no job swap online), edges live for exactly one host frame. Guest keyboard (built in `Net.padNow`, the host never sees keys): WASD move, Space = a (roll / dig), E = x (held spell), T = y (tree); a real pad is sent as it is. While the guest's tree / menu / book is up he sends a neutral pad (`Net.mute`). Only intent: `buy` (`Net.hooks.buy` runs the normal `UI.buy` on the host with its toasts captured and sent back as `buyres`); everything else, re-entering after death included (`G.w.deadT` > 1 s and the roll button), is pad input through the sim.
- **Nothing freezes online**: `Main.step` ignores open trees / the grace beat when `Net.on`; the pause menu and the Book set `Main.menuUp` (not `G.paused`, which online is always false, so the snapshot never carries a pause); a tree or menu only holds ITS player's input (`Main.wizardOnly` for the host behind a menu; `Net.mute` for the guest). Losing window focus does nothing online. **Known limit**: a hidden host tab is throttled by the browser (rAF ~1 Hz) and the guest sees the game stall; keep the host's game tab visible.
- **Relay (not built in)**: first real test on one home Wi-Fi: both machines reached each other but ICE ended "disconnected" with only a hidden-local (mDNS) and a public candidate (router isolation / no hairpin NAT), so STUN-only is NOT enough on every home network. PeerJS's free community TURN (eu-0 / us-0.turn.peerjs.com) no longer resolves in DNS, so there is no free built-in fallback. **Verified 2026-10-26: a Metered relay (global.relay.metered.ca, ports 80 / 443, udp + tcp + tls) connected home Wi-Fi <-> phone hotspot where STUN-only could not** (the host sent 240 unanswered connection checks without it; with it a real session ran at ~114 KB/s, 5.3 KB snapshots, 145 ms ping). The relay is only used when ICE finds no direct path, so a direct pair costs nothing. Metered's FREE TRIAL is 500 MB total (~70 min of relayed play at that rate; paid tiers start at $99/mo), so it is a test, not a shipping answer: the options are Cloudflare Realtime TURN (free 1 TB/month, needs a tiny serverless function to mint short-lived credentials) or cutting the snapshot rate. **The permanent relay (2026-10-26, Josh chose it): Cloudflare Realtime TURN (verified in its docs: the first 1,000 GB are free, then $0.05 / GB; STUN free; the free allowance reset is not documented, check billing) minted by `api/turn.js` on Vercel, with the game itself hosted on Vercel too (the repo is imported with no build step: Framework Preset Other, empty build / output fields).** `Net.getRelay` (net.js) fetches `/api/turn` (or `?api=<url>`) before every `createRoom` / `open` and adds the returned `iceServers` (`Net.cfIce`); on file://, GitHub Pages, or ANY failure (not configured, 403, 429, 502, garbage, timeout 4 s) the game goes without and connects directly as before (tested against a mock endpoint in every failure mode). The relay is only used when ICE finds no direct path. Setup the owner must do once: Cloudflare dashboard > Realtime > TURN > create a key (key ID + API token); Vercel > import this repo > Settings > Environment Variables `CF_TURN_KEY_ID`, `CF_TURN_API_TOKEN` (and `TURN_ALLOWED_ORIGINS=https://slyhounddog-debug.github.io` if the Pages copy should get relay too). The old `?turn=` hook still wins when present (any TURN of your own choosing): open the game on BOTH machines with `?turn=<turn:host:3478>&tuser=<name>&tpass=<secret>` (`Net.relay`). `Net.diag` / the join error report the ICE state and candidate kinds seen.
- **Smoothing on the guest** (2026-10-26; the first build drew every snapshot as it came and looked choppy: 45% of screen frames showed a walking Wizard in a new place, now 97%): the host stamps a stable `uid` on everything that moves (`Net.stamp`, just before `Snap.wire`: enemies, allies, projectiles, drops, pickups, boulders, zones, mines, boomerangs, arcs, flying items; `G.w.uidN` is the counter), and `Main.tween` (online.js) matches the new snapshot to the one before by `uid`: each moving thing (x / y, the Wizard, the Builder, belt items, animation clocks, arcs) starts again from where it was DRAWN and glides to where the host says it is over about one snapshot interval (`Net.snapGap`, 40-120 ms), `Main.tweenStep` advancing it every frame. Jumps over a few tiles (blink, respawn) are not smoothed. The guest still sees the world about one snapshot (+ the network delay) late, and his own Wizard answers his keys only after a round trip (no client prediction: Phase 2).
- **Layout**: each player's own world fills the stage (`R.drawFactory / drawWorld(ctx, dt, rect)`, `R.rect = { x0, w }` is what everything inside reads instead of `CFG.HALF`); the partner's world is drawn by the same renderer at its natural size on a scratch canvas and an 800 x 500 crop around the character is shown bottom-right (`R.drawPip`, `R.pipRect`; host sees the Wizard + his HP / armour, guest the factory). Size = Settings > PARTNER VIEW (`AU.settings.pip`, 0-45 % of the stage width, default 28, local, never synced). CSS `#game.onHost` / `#game.onGuest` rearrange the DOM HUD (guest: no Builder HUD, Wizard card top-left, minimap top-right). The photo test's default rects are the offline halves, so it still audits the same draw path.
- **Guest loop** (`Main.guestFrame`, `STATE === 'guest'`): takes the newest whole snapshot (`Net.takeSnap`: swapped in atomically, never mutated), sends its pad, draws, runs the HUD (`UI.updateHud` with guest guards: `questSide` / `updateQuest` only read, the Builder-only cards are skipped, `UI.buy` / `undoBank` / `pin` are intents or no-ops). The guest writes no save (`Main.save` returns early), plays music + UI sounds only (world SFX stay on the host: Phase 2).
- **Disconnect**: no packet for 8 s (host) / 6 s (guest) or a closed channel = lost. Host: the sim freezes, a banner counts 60 s (`Net.REJOIN_MS`) with the code; the same guest rejoining gets a fresh handshake + full snapshot and play resumes; after 60 s `Main.toTitle()` (the save is intact). Guest: CONNECTION LOST with REJOIN (same code) / TITLE; the host ending the game says so.
- **State moved for this**: the harvestables' and forage spots' changing fields (hp, broken, respawn, flash, surf; prog, lastT, shake) now live sparsely in `G.w.hv` / `G.w.fg` (keyed by node id) behind accessors made by `WZ.nodeProps` (the module objects are still the static layout, `WZ.bucket` is allowed in the photo test). They survive a death (`WZ.reenter` carries them over) but a new game / load starts them fresh. The Builder's facing flip (`bd.flipS`) is worked out in `FA.moveBuilder`; the renderer only reads it.
- **Client-side prediction of the guest's own Wizard (2026-10-27, `Net.VERSION` 4)**: on a 150 ms ping the guest's key press showed 275 ms later (even with no network delay the pipeline added ~110 ms), which is unplayable for steering. Now the guest steps a private copy of his Wizard every frame (`Main.walkStep`, online.js: a MIRROR of the walk / roll block of `WZ.update`, **keep them in step**; `WZ.update` itself is untouched so offline is identical) and draws that (`Main.predictFrame` overwrites the snapshot's Wizard fields after the glide). Pad packets carry a counter `q` (kept in `Net.hist`), the host stamps `G.na` = the last `q` its sim used (`Net.aseq`, in `Net.stamp`), and each snapshot (`Main.predSnap`) restarts the copy from the host's Wizard and REPLAYS the packets newer than `na`; the difference to what was drawn fades over ~0.1 s (`Main.pr.ex / ey`; > 2.5 tiles snaps). Not predicted (the host's picture is shown as is): death, a geyser jump, the Circlet's blink, recoil (`w.kick`), a dig. Pads go out at 60 Hz and at once when the input changes; the host sends a snapshot right after a changed input (`Net.snapNow`) instead of waiting for the 20 Hz slot. Measured with `Net.simDelay` (test only: ms held back on each side) in tools/nettest: key -> own Wizard moves 273 ms -> 42 ms at 150 ms ping; a zig-zag + roll ends 0.001 tiles from the host. `?predict=0` turns it off; the guest's pause menu shows `predict fix` (the average miss per picture, tiles). Everything else the guest sees (foes, spells, the Builder) is still one round trip + a snapshot old by design.
- **Prediction timing (2026-10-27, no wire version change from 4: only new G fields `nat` / `nft`)**: the first prediction build still tugged back and forth while walking straight (real test: `predict fix 0.16`). Three causes, all fixed: (1) the replay did not know how long the host had already used the acknowledged packet; (2) times mixed `performance.now()` (when code happened to run) with the frame clock the sim steps on; (3) a new snapshot replayed up to now and the same frame then stepped one frame more. Now everything is on FRAME timestamps: the host stamps `G.nft` = the rAF timestamp its sim was stepped to (`Net.drive(ts)` from the main loop) and `G.nat` = how long before that the sim started using packet `na` (a packet counts from the start of the first frame interval that uses it); the guest records each packet at the start of the frame interval its own stepping applies it over (`Net.prevTs`), learns the clock offset D = sent - started as the LARGEST of the last 40 samples (`Main.pr.dq`: delays only make a sample late), replays from `nft + D` up to the moment the current copy stands for (`Main.pr.lastTs`), and `Main.predictFrame` steps on from there. Measured: a straight walk at 150 ms simulated ping corrects 0.001-0.008 tiles a picture (was 0.045-0.1); what is left are real surprises (a foe bumping him). `Main.pr.last` holds the last correction (diagnostics, `TRACE=1` in tools/nettest prints them).
- **Drawing cost (2026-10-27)**: the guest drew 34 fps on the real test laptop. Profiled (tools/nettest `PROFILE=1 THROTTLE=4`: per-function ms a frame on both sides + the guest's CPU profile): ~2000 ground diamond fills a frame at the guest's full 1600 width, and the partner view redrawing a whole second world every frame (host 16 ms at 4x). Fixes: **the ground cache** in render.js (`GROUND` / `groundChunk` / `drawGround`: 16 x 16 tile chunks drawn once from `WZ.terrain` / `WZ.palette` and pasted back to front; a module variable, not on `R`, so the photo test never sees it; pond glints, bog marks, scorch, chasms and spell ice / walls still draw every frame; `R.noGroundCache = true` draws the old way) and **the partner view at ~24 fps** (`R.drawPip`: the scratch canvas is redrawn when 1/24 s has passed, pasted every frame). Measured: the wilds 10.6 -> 3.7 ms at 1600 wide, 6.0 -> 2.6 ms at the offline 800 (offline gets faster too); the guest at 4x throttle 22 -> 36 fps. **Flagged**: the cached ground is not bit-identical to the old per-tile fills (about 3% of pixels, along tile edges, differ by at most 5 / 255 in one channel: edge anti-aliasing composited from a chunk instead of onto the neighbour tile); invisible, and the photo test is unaffected (both its frames use the cache), but offline frames are no longer pixel-identical to builds before it.
- **Snapshot interpolation (2026-10-27)**: after prediction and the ground cache the real test read 57 fps drawn yet felt like 30 with dips: everything the guest does not predict glided toward each picture AS IT ARRIVED (`Main.tween` / `tweenStep`), so any picture that came a little late (always: jitter, and the host sends an extra one after an input change) left foes standing for a frame or two (measured: 24% of screen frames showed a walking foe not moving). Now, in the game, the guest buffers the pictures with the host's timestamp `G.nft` (`Main.sb`, `Main.sbPush`) and each frame shows the host moment `now + (largest nft - arrival of the last 40) - Main.interpDelay` (one picture interval + the measured jitter (largest minus 5th percentile) + 15 ms, 65-250 ms), blending the two pictures either side of it by their timestamps (`Main.interpFrame`: G becomes the later one, `Main.tween(A, B)` lists the moving fields, k from the times, up to 60 ms of carrying on past the newest when one is late). The picture on show is restored to the host's own numbers before it becomes the "from" side (`Main.sbRestore`, incl. the Wizard fields the prediction wrote, `Main.wRaw`). The guest's own Wizard is NOT delayed (`Main.predSnap` runs on the newest picture at arrival with G swapped to it for the call). The menu world and the hand-over still use the old arrival glide. Measured (tools/nettest `MOTION=1`, `JITTER=<ms>`, test-only `Net.simJitter`): foe stalls on the guest = foe stalls on the host (2% / 2% clean, 12% / 13% with 20 + 0-30 ms jitter), i.e. the netcode adds none. Cost: foes, spells and the Builder show ~65-100 ms later than before (the pause menu shows `world -N ms`). `?interp=0` turns it off.
- **Phase 2 (not built)**: TURN / relay fallback, the host choosing a role, entity ids + snapshot interpolation, world SFX for the guest, delta snapshots, mid-run join by a new guest, job swap online, **data-driven timers** (`G.w.timers[].fn` closures never cross the wire: the host keeps simulating and the guest only renders outcomes, so they stay as they are unless host migration or a simulating guest is ever built).
- **Testing**: `node tools/nettest/run.js` (functional run, `SOAK=600` for the soak, `SHOTS=<dir>` for screenshots; needs internet for the signaling server). It runs both pages on one machine: it proves the protocol and the game, NOT NAT traversal between two networks (`tools/netspike/spike.html` is for that). `__wands.Net` is the hook (`Net.stats` = snapshot sizes / rates, F3 shows them).

## Architecture essentials

- **Stage**: fixed 1600×900 internal resolution, scaled to fit the window (`fit()` in main.js). DOM overlays live inside `#stage` so they scale too (the studio intro is outside it, full-window). Left half (x < 800) = factory, right half = wizard.
- **8-bit pipeline (render.js)**: each half is drawn into a low-res buffer (`P` screen px per buffer px: factory `P=4`, wizard `P=3`) via `ctx.setTransform(1/P, …)`, so all drawing code still uses full-res stage coordinates, then the buffer is blitted with nearest-neighbour. Sprites are drawn at `S = P` so one sprite pixel = one buffer pixel. The camera and sprite positions snap to the pixel grid (`setView`, `snap`); the followed Builder / Wizard are snapped relative to the smoothed camera (`R.toScreenLocked`), not to the world, or they hop back and forth when the two round on different frames. **Text never goes through the buffer**: `txt()` and `R.prompt()` push closures into `R.defer`, flushed at full res after the blit (`R.flush`). `txt(..., 'd')` = Press Start 2P, otherwise Jersey 10 (`FONT_D` / `FONT_B`; both put the Silkscreen digit face first). Use 4px-multiple sizes and ≥4px line widths in the factory (≥3 in the wizard world) so shapes stay chunky.
- **Iso projection**: `sx = (x−y)·TW/2 + ox`, `sy = (x+y)·TH/2 + oy`. Tile (x,y) occupies [x,x+1)×[y,y+1); centres at +0.5. Factory `TW=80,TH=40`; wizard world `TW=60,TH=30`. A circle of radius r tiles ≈ diamond/ellipse with semi-axes `r·hw·√2`, `r·hh·√2`.
- **Grid directions**: `DIRS[0]=east(+x)`, 1 south(+y), 2 west, 3 north. "East" is down-right on screen. WASD/arrows move in *screen* directions, converted with `dx = ix + iy, dy = iy − ix`.
- **Factory layout** (`CFG.factory`): the grid is FIXED (48×36, `G.fac.w/h`) and only the tiles in `G.fac.land` (0 = nothing, 1 = floor, 2 = a Stockpile tile on the floor; saved as a string) are floor; `FA.owned(x, y)` (land >= 1) says whether a tile is floor (the Builder cannot walk off it, nothing can be placed outside it, a throw that lands off it bounces back). **The Stockpile part of this bullet is superseded by "Stockpile tiles" below** (there is no fixed Stockpile Zone, `FA.zone` / `FA.reserved` are gone). The floor starts as the 12×9 base rectangle and grows one **Floor Tile** at a time (building type `expand`, hotbar slot 8 / key 8): placed on empty ground right beside the floor (`FA.canExpand`), thrown 1 Wood + 1 Stone (+1 Iron from the 29th tile on, `CFG.factory.freeIron`; the cost is fixed on the blueprint as `b.cost`, `FA.costOf`, counted by `G.fac.added`), and when paid for the blueprint turns into floor (`FA.finishTile`, `G.stats.tiles`). There is no Factory Expansion skill node any more. The **Stockpile Zone never moves**: it is the base rectangle's south-west 5×5 (`FA.zone()`, `FA.piles()` are constants of the base). The portals stand on the east edge of the base (`G.fac.pp` = the Spell Portal's top cell, the Skill Portal 4 rows lower). **Old (v1) saves** were one rectangle: `FA.fromJSON` moves it onto the grid with its south-west corner on the base's (`FA.lastShift`, also applied to the Builder in `Main.applySave`); the tree key `expand` is ignored. 221Never hard-code coordinates: use `FA.W()/FA.H()`, `FA.portal('spell'|'skill')` (top cell), `FA.portalCells(w,h)`, `FA.zone()` (Stockpile Zone, SW corner) and `FA.piles()`. Both portals sit on the east edge (`spellY = floor(h/2)−2`, Skill Portal 4 rows lower). `FA.resize(w2,h2)` shifts everything so the portals stay on the east edge; things that would land in the new Stockpile Zone are refunded.
- **Grid cells** `G.fac.grid[y*w+x]`: a building, a belt `{type:'belt',dir,item}`, a portal `{type:'portal', which:'spell'|'skill'}`, or null.
- **Building kinds** (`CFG.buildings[type].kind`): `harness`, `crafter` (forge / cauldron / anvil), `cell` (the Battery and the Heavy Battery), and the logistics kinds `splitter`, `crate` (`FA.isLogi`). Every building has `dir` (output side), `out[]` (max 3 for machines, 2 for the splitter, `CFG.crateCap` for crates; items `{kind, charge?}`) and blueprint state (`done`, `got`). Logistics pieces push with `FA.updLogi` (rate-limited by `b.cd`; a Splitter routes by `FA.splitWays` / `FA.splitTook`, see Logistics below); `FA.pushSide(b, dir)` is the shared "push my first item out of this side" (it never pushes into a belt that points back at the building). There is no Sorter any more (a Splitter's element toggles do the filtering; an old save's Sorter is refunded and its contents set down on load); crates refuse raw resources.
- **Throughput feedback**: each frame `FA.state(b)` gives `'jam'` / `'starve'` / null into `b.st` with a timer `b.stT`; render shows `ic_jam` / `ic_starve` after 1.5s. Portals log entries in `G.fac.log` (last 60s) for the `N/MIN` labels. `G.fac.working` counts running machines (drives the hum and the music).
- **Items** (`ITEMS`): resources (wood/stone/iron + the rare **shard**), element packets (air/water/fire/earth), combo spells (one per forge recipe), pickups (potion, elixir, armor, plate), Spell Portal takes `FA.isDeliverable` (elements, spells, pickups, Eggs, garments, and Cores / Ward Keys only while the Wizard stands near the shrine / keep they open). Skill Portal takes `FA.isBankable` (= `BANK_KINDS`: elements, combo spells and Aether Shards, which the Summoning node costs). There is no Boss Sigil and no altar building any more (an old save's altar building is refunded on load). `FA.enterPortal(cell, kind)` routes either.
- **One insertion path**: `FA.canInsert` / `FA.insert` serve belts, machine outputs, hands and thrown items alike.
- **Spell context**: `WZ.cast` sets `WZ.ctx = {spell, el, hits, kills, weak}`; projectiles, zones and `WZ.later` timers capture it, so delayed hits still know their elements. `WZ.hurtE` applies `WZ.mult` (weak ×2, resist ×0.5; the boss ×1.6 on its weakness, ×0.4 otherwise) and counts unique hits per cast. 1.1s later `FA.landed(ctx)` pops "HIT n KO n WEAK xn" at the Spell Portal (combos always, basics only on weak hits).
- **Enemies** are made with `WZ.makeEnemy(type, x, y, elite)` (fields `spd`, `dmg`, `xp`, `rad`, `weak`, `resist`, optional `mark` / `guard` / `boss`). Biome foes (`w: 0` in `CFG.enemies`) are chosen by `WZ.pickType` from the terrain under the spawn point; elites by time + distance (`CFG.elite`). First sighting of each biome type / an elite toasts both halves (`G.w.seen`).
- **Landmarks** (`WZ.marks`, generated before decor so nothing overlaps them; run state in `G.w.lm[id]`): camps wake within `campWake` and are claimed when their foes (`e.mark`) are dead; crypts open after standing at the door `cryptHold`s and claim when the `guard` elite dies. `WZ.claim` drops shards + XP and bumps `G.stats.landmarks`. **Shrines** are claimed by the Builder sending THREE Cores through the Spell Portal, one of each element the shrine does NOT belong to (an Air Shrine takes Water, Fire and Earth), while the Wizard stands within `CFG.unlockR` of it: each one lands on the shrine (`WZ.unlockTarget` → `WZ.unlockLand`, progress in `G.w.lm[id].fed`, shown as Core icons that turn into checks over the shrine) and the third runs `WZ.claim` (`shrineShards` = 1; no mini-game, no roll button). Cores only count when they come through the portal: a Core that drops from a foe flies to the Stockpile first, it is never used on the spot. After that, while the Wizard stands on a claimed shrine, `WZ.updMarks` sets `G.w.shrine = el` and `FA.cycle` (via `FA.shrineBoost`) runs that element's harnessers `shrineBoost` (25%) faster. Claimed shrines are still updated each frame (the `done` skip excludes them). The visuals: a stream from the shrine into a little portal (wilds) and out of the Spell Portal into each boosted harnesser (`R.drawShrineStreams`), plus a pulsing rim.
- **Forage spots** (`WZ.forage`, generated after harvestables: dirt mounds, stick piles, berry bushes; `CFG.forage`): standing still (no move input) within `reach`, the Wizard's roll button calls `WZ.mash` instead of rolling; `taps` presses dig it up (mounds: Stone + maybe Iron, sticks: Wood, bushes: a potion or Shield Potion pickup). Progress decays when he stops; spots respawn. Presses for 0.35s after a mash never roll.
- **Rolls**: the Wizard strobes (see-through / white silhouette) during i-frames; hits the roll swallows (touch, orbs, slams) call `WZ.dodge` ("DODGE!" + `AU.sfx('dodge')`). `AU.sfx('roll')` is pitch-shifted randomly per roll.
- **Catch grace for every receiver**: a throw that comes down within `CFG.portalCatch` (1.35) tiles of a portal that takes it is pulled in (`FA.portalNear`), and now within `CFG.catchR` (0.7) tiles of any building or blueprint that is taking that item (`FA.catchNear`: `FA.canInsert` / `FA.canOver`, measured to the tile's rectangle) goes into it too, instead of onto the floor or bouncing. `FA.land` tries the portal first, then the nearest taker, for a throw that lands on empty floor, on a full belt or on a building that refuses it. Belts do not catch.
- **Deliveries cross the split**: `FA.deliver` calls `WZ.send(kind, 'spell' | 'pickup', spell)` (not `WZ.incoming` / `WZ.dropPickup`): `FA.suck` slurps the item in (`CFG.suck.baseT`), then `R.drawSuck` arcs it up and out of the factory's top-right corner (`CFG.arc.outT`); meanwhile `G.w.arcs` holds it with a negative `t` until it enters the wilds at their top-left and lobs down onto the Wizard (`CFG.arc.inT`, `R.drawArc`: a curved path, a trail, a shadow sweeping in over the ground, `AU.sfx('whoosh')`). On arrival (`WZ.arcTick`) a spell starts its drop-in; a potion / armor lands as a pickup on a dry spot picked when it came into view. Eggs and the Sigil keep their own arrivals. Dying clears the arcs.
- **Spell drop-ins (the Wizard's telegraph)**: an arriving spell calls `WZ.incoming(spell)`, not `WZ.cast`: a `drop` fx plays over the Wizard for `CFG.spells[s].drop` seconds (0.45-0.9) with the HI sound `incoming` / `incoming_big`, then a timer casts. `R.drawDrop(ctx, v, f, ground)` draws it twice (ground pass under bodies, air pass over them): a shared dashed ring closing on his feet that blinks at the end, chevrons along `WZ.aim()` for aimed spells, a target mark for Mud, and a themed scene per spell (gust streaks, fireball trail, spray droplets, tumbling boulder, flame column, steam puffs, sand funnel, oozing magma, storm cloud, mud blobs, meteor through a hot portal, crackling bolt, snowflakes + frost, a ground portal for Geyser, four element orbs for Nova). A new spell needs a `drop` and a case there.
- **Spell landing pulse**: `WZ.cast` (at the end of the drop-in) calls `FA.thump(tier, col)` as the spell bursts (tier = elements in it, 1-4): rings round the Spell Portal, sparks and a factory camera bump (`G.fac.bumpAmp`, sideways shake from tier 3).
- **Boss weakness at the portal**: while the Chimera is out the Spell Portal wears a rim in its weakness colour, shows that element in its middle and "BOSS WEAK: X"; on every change `G.fac.weakFlash` / `e.weakFlash` (`CFG.boss.weakFlash`) flash both.
- **Adjacency Overdrive**: a Forge or Cauldron with a done, charged Battery (any `cell`) on one of its 4 sides crafts `CFG.overdrive` (15%) faster (`FA.overdrive` → `b.od`). - **Input buffer**: a pick/use press (keyboard/pad) that finds nothing to do sets `G.ibuf` and retries quietly (`FA.interact(mode, true)`) for `CFG.inputBuffer` (0.1s) before showing the "why not" label.

- **Machine state language** (`FA.state`, set every frame into `b.st`): `work`, `missing` (some inputs), `starve` (none), `jam` (output waiting, `b.blocked` = the last push failed), `full` (buffer full), `off` (no power), or null. - **Audio hierarchy** (audio.js): `HI` sounds (deliveries, spell zaps, weakness change `weak`, danger cues `warn` / `heart` / `hurt` / slam / volley, dodge) go to `hiG` and `duck()` the `duckG` bus, which carries the music and `LO` sounds (hum, pickups, clicks, state chirps). Rapid repeats of a LO sound get quieter. The switch lives in `play()`; `tone` / `noise` default to the bus in `cur`. Low-HP heartbeat and the slam telegraph `warn` are the Wizard's danger cues.
- **Layered soundtrack** (`AU.layerMix`, `CFG.music`): four looping files, one per element, all exactly 4,960,627 samples (68 bars of a 118 BPM waltz = 103.35s, starting at the song's first note, the 2-beat pickup at 0.2s) and started on the same tick so they stay locked. Mapping: Air = Woodwinds, Water = Strings + Keyboard, Fire = Drums + Percussion + Synth + Other, Earth = Bass + Guitar + Brass. Each layer's volume follows `G.fac.weather[el]` (the same eased 0..1 that tints the wilds: packets/min, shrines, Portal Storms) through `CFG.music.curve`; Air never drops under `airFloor`, the others start at silence; the Chimera brings all four to full (a `music_boss` clip still overrides). The menu world (and the loading / intro frames) plays all four at `CFG.music.menu` (0.8, `AU.layerMix(null)`). **Muffle**: a low-pass on the music bus (`musLP`, `CFG.music.muffleHz` 2200 / `muffleT`) is closed in the menu world (`AU.muffle(true)` from the menu branch of the main loop), in the pause menu (`AU.hold`, which no longer silences the music) and while either skill tree is open (`AU.muffle` from `Main.step`); the music keeps playing its current mix underneath. Until all four are decoded the synth stays quiet; if one fails to load the old `music` override (`whimsical journey`, not loaded otherwise) or the synth plays. `AU.layerInfo()` shows the live goals. The loop wraps with the 0.5s of song after the loop end ringing on, fading out, under the start (overlap-add, so the opening notes stay at full level; an equal-power crossfade into the head faded the first note in), and Vorbis is used because MP3 encoder delay would click at the seam. **Every looping music file also runs through a loop envelope** (`loopEnv` / `tickEnv` in audio.js, `CFG.music.fadeIn` 0.5 s / `fadeOut` 1 s): each pass of each layer (and of a `music` / `music_boss` clip) fades in over its first 0.5 s and out over its last 1 s, scheduled a pass at a time from `schedule()`, so no intro / outro spike. To change the balance or mapping: edit `CONFIG` in `tools/musicbuild/build.js` and rerun it. **To change the loop start / end, use the dev tool's Audio tab > Game music** (hear the loop and its wrap, drag START / END, Save & rebuild): it writes `overrides/music.json` (`startSample`, `lengthSamples`, `xfade`), which build.js merges over `CONFIG`, then rebuilds the four files. Nothing else picks up or puts down — there is no hand-insert, hand-portal-send or put-back; throwing is the only way to put items in. Q no longer does anything. With a building selected, pad A places in front (hold with Belt to lay belts).
- **Interaction resolver**: `FA.findTarget(mode)` + `FA.actionFor(target, mode)` with `mode` `'pick'` or `'use'` → `{label, fn, rep}` drive the prompts (`R.focus.list`, up to one pick + one use bubble; key names from `R.key('pick'|'use')`), the buttons, click-to-walk-and-pick and **hold-to-repeat** (only `rep: true` pickups). With the mouse, the pick prompt follows the hovered thing (`FA.thingAt`). Add new interactions there, in the right mode.
- **Throws follow the lead line**: `aimNow()` (main.js) computes the aim for both the drawn line (`R.aim`) and `throwAlongAim()`, which throws at `R.aim`.
- **Pickups are one item per press** (`FA.takePile`, `FA.pickFloor`, `FA.takeOut`, belt grab).
- **Power**: global; `FA.power()` grants draw in placement order. Every Battery building (`cell`: Battery, Heavy Battery) with charge gives 10 power, no hauling: it uses its own charge automatically. The power actually drawn is split evenly over every charged Battery (`G.fac.perBat`), and each drains at `FA.drain(perBat)` = `perBat * batteryMax / (batteryLife * stationGen)` per second: a Battery lasts `CFG.batteryLife` (60s) at a full 10 power, 300s under one 2-power harnesser, 150s when 4 Batteries share 16 power. A Heavy Battery divides its own drain by 1.5 (charging time is unchanged). `FA.life(b)` is the seconds left at the current load.
- **Batteries are buildings, not items** (there are no Stations, Chargers or Battery items any more). A Battery (`battery`, 8 Wood + 6 Stone + 4 Iron, no unlock) and a Heavy Battery (`heavybat`, locked behind the Heavy Batteries node) are placed like any building: blueprint, materials thrown at it. State on the building: `bat` (charge 0..`batteryMax`, past full while overcharged), `fuel` / `types` (what is waiting to burn), `over`, `top` (topped up lately, so `G.stats.charged` counts once per charge). `FA.updCell` burns the fuel into charge (`chargeBase` / `chargeBoost`, as the Charger did), then the building gives power and drains with the load. It accepts element packets, Wood and Stone (`FA.canInsert`: belts, splitters, machines' outputs and throws all feed it) and combo spells / Elixirs overcharge it (`FA.canOver`). `G.flags.fed` = something was fed to a Battery (goal 6). The factory starts with ONE full Battery just south of the Stockpile (`FA.initial`, `(ox + 5, oy + 7)`). **Old saves**: a Station or Charger loads as a Battery (keeping charge and fuel), each loose Battery item (hands, floor, belts, outputs: counted by `FA.lostBat` / `Main.applySave`) and old `station` / `charger` credits come back as free Battery placements (`G.credits.battery`).
- **Wizard world terrain** has three classes: normal speed (grass, dirt, sand, flowers, dark grass, path), **slow** (`T_BOG`, × `CFG.world.slowTerrain`, for the Wizard and monsters) and **impassable** (`T_POND` — nobody can enter; paths over water act as bridges). Bodies move with `WZ.slide` (axis sliding vs water). Spells add temporary terrain in `G.w.tmod` (tile index -> `{ k: 'wall' | 'ice', t, dur }`, count `G.w.tmodN`): `WZ.tile` returns `T_WALL` (impassable, `WZ.wet` true) or `T_ICE` (full speed, walkable even over water) there, and `WZ.buildFlow` uses `WZ.wet`, so monsters path round walls and over ice (`WZ.flowDirty` forces a rebuild). Monsters detour sideways when blocked. Spawns, pickups and the re-spawn ring use `WZ.dryNear` so nothing appears in water; drops never fly into water.
- **World/run state** lives in `G.w` and is *not* saved (landmarks and the boss reset each expedition; `G.w.run` holds the per-run stats for the results screen). Saves persist the factory, stockpile (incl. shards), XP, **bank**, tree, goals, flags and stats (`G.stats` also tracks `xpEarned`, `packets`, `banked{}`, `time`, `elites`, `shards`, `landmarks`, `wins` for the debug overlay and the victory screen).
- **Saves**: `localStorage['wands2_save_slot1..3']`, `v: 4` (`SAVE_VERSION` in main.js). Anything older shows as "older version" and can't be loaded. `qv` (`QUEST_VERSION`, now 5) lets older v4 saves keep their place in the goal chain: goals 14-15 were inserted (a save without `qv` past goal 13 shifts by 2); qv 3 inserted the recharge goal; qv 4 inserted the first-creature-kill goal at 5 and the two Stronghold goals before Summoning (goal numbers from the old 5 shift by 1, from the old 21 (Summoning) by 3). Since **QUEST_VERSION 5** the single goal index became `quest: { B, W }` + `qbase: { B, W }` (`Main.questOf` / `Main.splitQuest` convert older saves: each QUESTS entry's `from` is the old chain index it continues; a track resumes at its first goal with `from >= old index`, new goals without `from` are skipped). Saves also carry `ev: { n }` (the event rotation index), `stock.core`, and `G.flags.core_<el>` (which Strongholds have paid their Core); `fac.eggQ` holds Eggs waiting at the Spell Portal. Bump `QUEST_VERSION` and add a shift whenever goals are inserted mid-chain. Autosave every 9s and ~1.5s after `UI.changed()`.

## Skill tree & economy (config.js `CFG.tree`)

- **Costs = XP + banked spells.** Spells are banked by sending element packets / combo spells (and Aether Shards, for Summoning) into the **Skill Portal** (`G.bank[kind]`, shown in the top bar and the tree's bank row).
- Two columns: **Factory unlocks** (Alchemy, Forge, Logistics, Armory, Heavy Batteries, Summoning: **none needs another building's node any more** (`req: []`), only its XP / banked spells (and Summoning a Warden Core), so they can be bought in any order; there are no Water / Fire / Earth Harnesser nodes, no spell nodes and no creature nodes: every element is available from the start, **spells and creatures are gated by production only**) and **Upgrades** (tiered tracks). The Collection Book lists every spell and creature. A pair spell needs only its two element packets at a Forge; a Triple needs its two parent pairs to have been MADE once (`CFG.recipes[id].parents`, checked in `FA.recipeOk` against `G.stats.made`), the Nova needs all four Triples made. Creatures: one **Creature Spawner** (building `spawner`) hatches any Egg whose packets are fed into it (1 / 2 / 3 elements = basic / pair / triple); no tier, no per-creature node.
- Unlock node: `{ xp, pay: {kind:n}, req: [ids] }`. Unlock XP is 1.5× the original spec values; element packets asked ≈ the XP cost (halved for Water, Alchemy, Fire, Earth and Forge), using elements available at that point (Water costs Air; Fire costs Air + Water; …), with pair/triple spells for late nodes.
- Upgrade track: `{ tiers: [xp…], kinds: [[elements per tier]], combos: {tierIndex: {spell:n}}, per }`. 5–8 tiers, each tier worth half of the original single upgrade (`CFG.upgrade`), cheap first (all tier-1 costs are below the original upgrade price) and steep last. Packets per tier = tier XP split across that tier's kinds. A tier implicitly requires the unlocks for the elements/spells it asks for (`UI.nodeReqs`). **Element spread (2026-10-28)**: every track's `kinds` rotate through different elements so the Builder keeps switching what goes into the Skill Portal instead of banking one element and moving on: tier 1 is one element (Quick Hands, Swift Harnessing, Wizard Zoomies and Hearty Hat start on Air because the goal gifts bank Air), the middle tiers are pairs that never repeat the previous tier's pair and differ from the other tracks at the same tier, then triples, and the last tier is all four. The whole tree asks for about the same of each element (Air 221 / Water 224 / Fire 223 / Earth 228 packets); keep it that way when editing `kinds`.
- Tracks: Swift Harnessing (8, +12.5%), Quick Hands (3, +30% hand-harnessing per tier; its tier 1 is the cheapest purchase in the tree: 3 XP + 1 Air), Swift Belts (6, +15%), Bigger Satchel (5, +1), Wizard Zoomies (6, +6%), Hearty Hat (8, +12 HP), Gem Wisdom (8, x1.125 on every gem drop chance per tier, capped 95%), Loot Magnet (5, +0.35 tiles of pickup range per tier).
- **Rebalance (2026-10)**: the tree literal in config.js is still the old price list; `CFG.costScale` (`xp: 0.7`, `pay: 0.5`) is applied once right after the dev-tool overrides (XP and banked-spell costs rounded, never below 1; upgrade tracks keep `pk`, the old XP basis halved, from which `UI.nodeCost` works out each tier's packets). The 27 original nodes went from **3,481 XP / 3,226 packets** to **2,437 XP / 1,629 packets**. The 10 new nodes (Spawner II / III, the 7 pair + triple creatures, Loot Magnet) are priced directly in the new scale (552 XP, 253 packets) and added after the pass. Whole tree now 2,989 XP / 1,882 packets. A node may also cost `core: n` Warden Cores (Spawner III and Summoning, 1 each): `UI.nodeCost` returns `core`, `canAfford` / `costHtml` / `buy` / the pin card handle it.
- **Spells and creatures left the tree (2026-10-25)**: removed 20 nodes (11 spells, Spawner II / III, 7 pair + triple creatures) worth 1,040 XP / 559 packets (+1 Warden Core); the six remaining Factory unlock nodes got a further 10% trim (`CFG.costScale.unlock` 0.9: 373 XP / 237 packets -> 337 / 213); the 49 upgrade tiers are untouched (1,267 XP / 907 packets). The tree is now 1,604 XP / 1,120 packets. **Refund on load** (`Main.refundTree`, `REMOVED_NODES` / `REMOVED_EXPAND` in main.js, `TREE_VERSION` 2): a save that owns any removed node (spells, creatures, Spawner II / III, and the earlier Water / Fire / Earth Harnesser nodes and Factory Expansion tiers) gets its XP, banked spells and Core back in full, the keys are dropped, pins on them cleared and a toast says what came back; spells it had unlocked count as made so Triples stay open.
- **XP is whole gems only**: no fractional XP anywhere. Kills roll gems (`CFG.enemies[t].gem = [guaranteed, chance of one more]`, `CFG.creatures[id].gem`; elites always `CFG.elite.gems` = 3; the Chimera 25; landmarks `xpBonus` gems); Gem Wisdom multiplies the *chance* (x1.125 per tier, `CFG.gemCap` 95%); resting gems within `CFG.bigGem.r` merge into one Big Gem (bigger sprite, rising cue). Wild chances: slime 30%, sprite 40%, shroom 45%, imp 50%, wisp 55%, lurker 60%, golem 65%. Old saves round `G.xp` down on load.
- `G.tree[id]` is `true` for unlocks and a tier number for upgrades — read levels with `lvl(id)`. Recipe unlocks: `CFG.recipes[id].tier` (spell recipes use their own spell id).
- **Opening either skill tree pauses the whole game**: `Main.step` skips `FA.moveBuilder`, `FA.update` (machines, belts, flying items) and `WZ.update`, zeroes both players' inputs and stops play-time/metrics. Toasts, goals and the music keep going.
- **Hover cards**: hovering a tree node shows `#nodeTip` beside it (`UI.showNodeTip` / `UI.nodeTipHtml`): description, a NOW / NEXT table from `UI.nodeStats` (upgrade effects computed from `CFG.upgrade`; unlocked buildings + recipes; spell recipe, craft time and the `dmg` blurb from the spell's tree node, which must be kept in sync with `WZ.cast`), then the cost.
- **Armory** costs half of what it did (34 XP, 9 Air + 15 Fire + 10 Earth before the scale pass). **Summoning** costs XP + packets of every element + **6 Aether Shards** (no Warden Core: they are gone) (`CFG.altar.shards`, set after the scale pass so they are not scaled; the Builder throws shards into the Skill Portal like any banked item, Q / pad X undoes one). Buying it places the Altar (see **The Summoning Altar**).
- Tier 1 of every upgrade track asks for `CFG.firstTierPay` (0.5) of the usual packets (`UI.nodeCost`).

## Design direction & deviations from spec v5.0 (intentional — keep them)

The user has asked, over several passes, for: a fleshed-out, active, rewarding factory loop; polish, animation and an inviting UI; intuitive mechanics; tight movement; pickup + throwing; nothing ever disappearing from hands; potions and armor crafted in the factory; then an **8-bit pixel-art** look with big retro fonts and no emoji; a much longer, spell-funded progression; terrain with blocking water; a smaller starting factory that grows; and the "Pardon My Games" intro from the handoff. They allow stripping/reworking spec features when there's a better way.

1. **Physical items & throwing.** Items lie on the floor (`G.fac.floor`) and fly (`G.fac.flying`). **Right-click / pad B** throws one item (hold = rapid) exactly along the lead line: at the cursor with the mouse, otherwise auto-aiming (`FA.throwTarget`) at portals, machines, blueprints, the Stockpile Zone or empty belts. Rejected throws bounce back.
2. **Hands never lose anything** (`FA.dropHands`, `FA.stash`). No code path may delete a held item. **The hands are one pile of single items** (`G.hands`, an array of `{ kind, charge? }`, bottom first, saved as `hands`): at most `FA.cap()` items IN TOTAL whatever mix (5 + 1 per Bigger Satchel tier), and last in, first out: the last thing grabbed is on top and is what a throw sends first. Helpers: `FA.top()` / `FA.topKind()`, `FA.canHold()`, `FA.addHands`, `FA.takeOne` (pops the top); always test `G.hands.length`, never `G.hands` itself. Older saves (one `{ kind, n }` stack, or a stack queue) are expanded on load; items over the cap land on the floor. The Builder carries the pile drawn item by item above his head (no numbers); the top-left HANDS card is a grid of small slots (cap many, the top one lit) beside the POWER card (`.hrow`). Holding pick sweeps up more of the top item's kind; Shift + throw sends the whole pile.
   **Slight pickup range** (`FA.autoPick`, `CFG.autoPick`): loose floor items that have lain still for `delay` and are within `r` (1 tile) of the Builder hop into his hands one per `gap` seconds (r 0 = off); the pick button still takes anything within reach. There is no tooltip over floor items or the Stockpile (`R.drawFocus` skips them): the item the pick button will take hops, shows a ground ring and orbiting sparks (`R.pickOf` / `R.pickFx`).
3. **One-at-a-time pickup** with hold-to-repeat on left-click / pad A (see above).
4. **Hotbar**: 8 slots (keys `1-8`, wheel, `[`/`]`, pad LB/RB) replace the spec's carousel: Hand, Belt, the Harnesser, four **families** (`CFG.families`: Crafters, Power, Logistics, Creature Spawners) and Floor Tiles. A family slot shows its current member (`G.fam`, last picked, else the first unlocked) with pips; **Q**, the wheel over the slot, or pad **RT** cycles the unlocked members (locked ones are skipped but shown greyed in the hover strip); `G.selected` is always a building id, so placement is unchanged; **R still rotates**. `UI.select(slotOrBuilding)`, `UI.cycleFam`, `UI.slotOf`. Slot 1 "Hand" = click to walk / walk-and-pick-up.
5. **Rotatable outputs** (`b.dir`, R rotates placement for belts and buildings).
6. **Machine output buffers are grabbable**; empty Harnesser → hand-gather with E. **The meter never fills by itself**: only taps of E fill it (`CFG.manual.taps` = 8 taps per packet; `FA.tapGain`; the Quick Hands track makes each tap +30% per tier). **The cranked amount is kept per Harnesser** (`b.hand`, 0..1, saved as `hand`): walking away or cancelling never resets it, the next E picks up where it stopped, and a small second bar shows it on the machine until the packet is made.
7. **Alchemy Cauldron** (element packets only: potion 2 Water + 1 Air heals 35; elixir 2 Water + Earth + Air heals 80; Shield Potion 2 Earth + Fire = +35 armor, Greater Shield Potion = +70; the ids are still `armor` / `plate`) and the **Armory** (`anvil`, forges the Wizard's garments). Pickups fall beside the Wizard (on dry land) and are walked over; armor (max 100) soaks damage first.
8. **Any input from any source** (belt / hand / throw). **Belts carry what machines make, never resources**: `FA.beltOk(k)` = `!RES[k]`, so Wood / Stone / Iron / Shards / Cores / Ward Keys can only be thrown or carried (belts, splitters and crates refuse them; an old save's resource on a belt drops beside it).
9. **Two portals**: Spell Portal (to the Wizard) and Skill Portal (bank for the tree).
10. **Economy**: belts start at half speed (0.9s/tile); building costs were 1.5× the spec, then cut ~30% (belts stay 1 Wood; the Splitter costs 2 Wood + 1 Stone); the Harnesser runs 10% faster than the spec (`CFG.harness`: Air 3.41s, Water / Fire 5.11s, Earth 6.25s); 50% more trees/rocks/ore in the wilds, then +10% (`CFG.harvest`, `CFG.forage`; broken nodes respawn after `CFG.world.respawn` = 120s, forage spots after 150s / 240s); the factory starts as a 12×8 floor and grows by placed Floor Tiles (see Factory layout); the Stockpile never moves.
11. **Guided goals, two tracks** (`QUESTS.B` = Builder, 25 goals; `QUESTS.W` = Wizard, 22 goals), each player with their own card (`#questB` over the factory half, `#questW` over the wilds) and they progress independently, at the same time. XP + an optional `gift` ({ bank, stock, credit, pickup }: skill-tree spells, materials, a free building placement, potions / armor that drop beside the Wizard), on-screen pointers, a fanfare on completion (`UI.questDone`). A goal is either `done(g)` (state / flag) or `stat(g)` + `n` (a lifetime counter that must grow by n SINCE the goal showed: baseline in `G.qbase[side]`, bar automatic) so practice goals ("charge 3 Batteries", "finish 10 monsters with combo spells") ask for fresh work. Both end at the boss: the Builder's last goal is sending the Sigil, the Wizard's is beating the Chimera. See **Goals** below.
12. **Feel**: acceleration/friction movement, squash & stretch, dust, camera look-ahead, screen shake, damage numbers, kill puffs, roll afterimages (8-frame somersault), spell-arrival sparkles, portal flashes.
13. **8-bit UI**: Press Start 2P + Jersey 10 everywhere, digits always Silkscreen (all bundled), stepped pixel borders (`.px`), no rounded corners or soft gradients, all icons are sprites (`ic_*` in sprites.js; `UI.img`; `data-ic` placeholders in HTML). Do **not** reintroduce emoji or non-pixel styling.
14. **Studio intro**: the handoff's Finsanity-quality "PARDON MY GAMES / STUDIO PRESENTS..." splash plays after the loading click, then the menu.
15. **Menu**: the living menu world (see **The living menu**): New, Load, Online (a globe), Settings (a gear), How to Play (its tabs - The Idea / Factory / Recipes / Wilds - are pages of one window, generated from the same `HOWTO` table as before) and Achievements (a trophy) are floor plates along the top-right edge; there is no Continue (Load a slot), no Controls in the start menu (pause menu only) and no DOM menu.
16. **Win condition**: kill THE Warden (the one Stronghold), buy the Summoning node (6 Shards + XP / packets) → the Summoning Altar falls into the wilds beside the Wizard → once the Warden is dead he lights its four sockets by hitting it with one spell of each tier (a Single, a Pair, a Triple, the Nova; each stays lit for good; before that "THE WARDEN STILL LIVES" rises off it) → with the Wizard standing at it, the Altar summons the Primal Chimera. Its weakness rotates, so the Builder must re-route which element reaches the Spell Portal mid-fight (that's what a Splitter's element toggles are for). Beating it shows the victory screen; play continues.
17. **Elements matter**: biome foes (Ember Imp / Bog Lurker / Gale Wisp / Stone Golem) and elites have weaknesses; first sightings toast *both* halves, so the Wizard's situation becomes the Builder's production order.
18. **Aether Shards** are the rare resource: only landmarks (camps, crypts) and elites give them; they gate the Spawners, garments, Ward Keys and the Summoning node (6, through the Skill Portal). **Shrines** replaced the old "send that element while I stand here" ping: the Builder claims one by sending the Cores of the three other elements (dropped by their creatures) through the Spell Portal while the Wizard stands near it (the claim pays 1 shard), after which standing on it makes that element's harnessers 25% faster.
28. **Show, don't tell**: on-screen words were cut back in favour of icons, key caps, particles and animation (see the "Show, don't tell" note above).
26. **Foraging**: mounds, stick piles and berry bushes give the Wizard a mash-the-button way to find basic resources and the odd potion / armor without the factory.
29. **Powered start**: the factory begins with one full Battery building just south of the Stockpile (see **Batteries are buildings**). The first time any Battery falls under `CFG.chargeTipAt` (50%) a toast + pop on it says to throw element packets, Wood or Stone at it (`G.flags.chargeTip`, only if nothing was fed yet). Goal 6 ("Feed the Battery", flag `fed`) teaches it. The POWER card also shows the **total charge** of every Battery building (`#batFill` / `#batTxt`, an overcharged one counts past full) against what they could hold.
30. **Builder movement**: speed 5.5; the walk pivots at the hips, leans back and forth, stretches on the push-off and skews off-axis (`R.drawBuilder`).
27. **Layout rewards**: Adjacency Overdrive (a Battery beside a Forge / Cauldron) and the Heavy Battery (longer life).
19. **Logistics**: Splitter, Storage Crate (unlocked by the Logistics node). The **Splitter** is a router with no front (its `dir` is ignored; R / `FA.rotateAt` skip it, the ghost shows no arrow). `FA.splitConn(b)` runs every frame: the side a belt points in from, a building points its output at, or another Splitter pushed from (`b.src[dir] = id`, set in `FA.pushSide`) is an input (`b.ins`); every other side with a portal, belt or machine (not a Battery, which only takes fuel but is an output too) is an output (`b.outs`, up to 3, in side order; colours `FA.splitCol` pink / cyan / gold). When the set of outputs changes (`b.sig`) the shares reset (`FA.splitReset`: 100, 50 / 50, 34 / 33 / 33). `b.pct[dir]` = share (always 100 in all), `b.filt[dir]` = item kinds an output is limited to (the dual-filter router: Fire + Earth left, Water + Air right); `FA.splitWays(b, kind)` = the outputs whose filter has that kind, else the unfiltered ones, ordered by a smooth weighted round robin on `b.acc` (`FA.splitTook`: every way earns its share, the taker pays the total, so shares are exact); no way = blocked. Pick or use opens `#splitModal` (`UI.openSplit`): an iso diagram (grey arrows in, coloured arrows out), then 2 outputs = one slider, 1 or 3 = a slider each (`UI.splitSet` keeps the others' ratio so it adds to 100), and a row of four element toggles per output (`UI.splitToggle`), RESET, DONE. Inputs while open (`Main.controls`): W / S or stick picks an output, A / D nudges by 5, 1-4 toggle elements (hotbar keys are off), pad X moves the element cursor, Y toggles, E / Esc / A / B / right-click close. Rows are rebuilt by `UI.splitSync` when `b.sig` changes. `R.splitArrow` draws each output's arrow (sized by its share) and its filter icons up close; the percentage itself is written only in the settings modal. `pct`, `filt`, `sig` are saved; old saves' `split` / `ang` are converted to the two sides they meant. Belts already merge, so there is no merger. Crates never take raw resources, so the Stockpile still can't feed belts by proxy.
20. **Readable factory**: jam/starve icons, portal per-minute rates, faded product ghosts in empty output slots, recipe purpose shown at the crafter you stand at / hover, "STARVED" / "BLOCKED" in the inspector.
21. **Goal pointers**: gold arrows in both halves, edge pointers with distance in the wilds, blinking hotbar slot / tree buttons.
22. **Pause clarity**: opening a skill tree freezes both halves and shows a big "WIZARD PAUSED" banner on the right (or "FACTORY PAUSED" on the left). The pause menu (Esc) has Resume / Settings (`UI.settingsPage`; the menu world has its own volume plates) / Save & Title (the way back to the menu world, see **The living menu**) and holds the music (`AU.hold`). Losing window focus or hiding the tab opens the pause menu and suspends the audio context (`AU.sleep`); audio wakes on focus, the game waits for Resume.
23. **Spell arrival** (Builder side too: the Spell Portal slurps the item in along a spiral, then it arcs up and out of the factory's top-right corner and sails into the wilds from their top-left (see Deliveries cross the split); `FA.suck` -> `G.fac.sucks`, drawn by `R.drawSuck`, tuned by `CFG.suck` / `CFG.arc`. A throw that lands within `CFG.portalCatch` (1.35) tiles of a portal that takes it is pulled in (`FA.portalNear`), so nothing piles up beside it): a mini portal opens over the Wizard and the spell plays its own short themed drop-in (a telegraph, so the Wizard's player knows a spell is coming without watching the Spell Portal), then casts and bursts; combos also show their name under him, and the Builder gets a hit report at the Spell Portal.

- Early-game power: the starter factory (second Air Harnesser -> Spawner I -> the Spell Portal's lower cell, on row `spellY + 1`) draws 2 + 2 + 1 = 5 of the Battery's 10, so it never browns out, but with the egg line running a Battery lasts about 120s: the half-charge tip toast (see Powered start) matters.

## Feel, weather and terrain spells (2026-10-23 pass)

All of this is plain data in `G` (snapshot-safe; the photo test was run with every one of them active).

- **Machine recoil & exhaust**: a Forge or Cauldron finishing a craft sets `b.thump = CFG.thump` (`R.drawBuilding` squashes it down, stretches it up, settles) and `FA.exhaust(b, inputs)` puffs particles out of its top (`p.sz` sized, rising: steam for Water, sparks for Fire, wisps for Air, grit for Earth, grey smoke for none).
- **Throw impacts**: every throw that goes in (belt, machine, portal, overcharge) pushes `G.fac.rings` (`FA.impact`: a tiny ring leaning the way it flew + three chips). A rejected one (full belt, full buffer, wrong item, a portal that refuses it) no longer just drops: `bounce()` in `FA.land` launches a `boing` flight back toward the Builder (`CFG.boing`, never into a building; `R.drawFly` wobbles and tumbles it; `AU.sfx('boing')` = click + spring), which lands on the floor.
- **Spell decals** (`G.w.decals`, `WZ.decal` / `WZ.mark`, cap `CFG.decalMax`): each spell's `dec` in `CFG.spells` (`k` burn / crater / crack / frost / wet / scorch / sand / mud / scuff, `r` x the blast radius, `t` 3-5 s, `a` strength: light spells faint and short, heavy ones deep). `WZ.explode`, chain hits, plain projectile hits and the ring spells call `WZ.mark` (only while a player spell's `WZ.ctx` is set, never on water); a new hit on the same spot renews the mark. `R.drawDecal` builds every shape from the decal's seed so it holds still while fading.
- **Grass that leans**: `WZ.bendTick` (after the enemy loop) marks `BENDY` decor (tufts, flowers, bushes, reeds) within reach of the Wizard and of big walking foes (`rad >= CFG.bend.bigRad`, elites, the boss; their walking velocity is `e.mvx / e.mvy`) in `G.w.bend` (key = bucket index x 32 + slot -> `{ t, d }`); `R.drawWorld` skews the sprite (`dsprSkew`) by a held lean that springs back with a damped wobble, plus a sway from Air weather. `WZ.generate` sows `CFG.bend.tufts` extra tufts (`tuft2`, `tuft3`, reeds in bog) with their own RNG after everything else, so nothing else moved.
- **Recoil**: aimed spells (Fireball, Spray, Boulder, Flamethrower, Magma) call `WZ.recoil(aim, S.recoil)` -> `G.w.kick`: a short shove backwards through `WZ.slide` over `CFG.wizard.kickT`, drawn as a lean back + squash that scales with the push.
- **Weather from the factory**: `FA.elTick(el, n)` counts element packets harnessed, hand-gathered, burnt in a Battery or crafted with (`G.fac.elAct`, an exponential window of `CFG.weather.tau` s); `FA.updWeather` eases `G.fac.weather[el]` (0..1, `CFG.weather.ease` per s, so it turns slowly) toward its packets/min between `min` and `full`, plus `shrine` while a claimed shrine or a Portal Storm boosts that element. `R.drawWeather` washes the wilds in each element's colour and adds Fire embers, Water rain, Air wind streaks (and grass sway), Earth dust; several elements mix.
- **Portal pressure waves**: `FA.pressure(amp, col)` (the Wizard losing `CFG.pressure.hit` of max HP in one hit in `WZ.damage`, an event starting, a Warden waking, the Chimera rising) pushes `G.fac.waves`: rings roll across the floor from the Spell Portal, the portal flashes, and `FA.quake(x, y)` jitters + flickers belts and machines as the front passes (within `range`).
- **Overclocking Batteries**: a combo spell (2+ elements) or an Elixir thrown into a Battery building (`FA.canOver`, in `FA.accepts` / `FA.throwList` at low priority so auto-aim still prefers the portal) adds `CFG.overcharge.fill[tier]` (or `elixir`) of a Battery past full, up to `max` x, and sets `b.over` seconds of +`power` (`FA.power`); a crackling rim, arcs and a second bar for the charge past full. `b.over` is saved.
- **Terrain spells** (`G.w.tmod`, see Wizard world terrain): **Mud** raises an Earth Wall (`WZ.wall`: `spells.mud.wall`, a line of blocks across the way toward its target, never on water or on him; foes caught inside are shoved out; `R.drawWall` rising / crumbling blocks, depth-sorted). **Blizzard** = Flash Frost (`WZ.freeze`: bog and water within its radius turn to ice for `frost.t` s, re-freezing round him every `frost.every` s while its zone follows him; ice never melts from under his feet). **Geyser** = Geyser Jump (`WZ.launch`: `G.w.jump` throws him up to `jump.dist` tiles ahead to the farthest dry, non-bog spot, `jump.T` s in the air, untouchable (`WZ.damage` returns), a somersault and a landing squash). The tree descriptions and hover-card lines mention them. `SPV` previews don't show the terrain parts.

## The one Harnesser, physical item stacks (2026-10-24 pass 2)

- **One Harnesser** (`type 'harness'`, `b.el`): carries Air / Water / Fire / Earth. `F` (Shift + F back, pad LT + X) calls `FA.cycleElem` on the Harnesser in reach (`FA.harnessNear`; a third prompt bubble shows it). `FA.setElem`: the old crystal bursts into particles, `b.grow` restarts at 0 and the new crystal grows `CFG.harness.growT` (15 s; switching again restarts it); nothing is harnessed or hand-gathered meanwhile (`FA.growing`); when grown it shakes and sparkles `shakeT` s (`b.shake`), then makes packets. A newly built one also grows first; the starter one is grown. Per-element cycle and power are in `CFG.harness`. Saves: `el` + `grow`; old `air` / `water` / `fire` / `earth` buildings load as a grown Harnesser of that element.
- **Buildings show no stacks of spare items** (`R.pile` is only left for blueprints, a Crate's contents and Eggs waiting at the Spell Portal; the Battery's fuel is a face gauge): what a Harnesser or crafter holds is a segmented bar of lamps set into its front (`R.pips`: lit = held / made, faint = a recipe input still missing; a crafter's finished product is one item beside it with a dot per extra one). ## Dev Wizard bot (solo iteration testing)

A **developer tool, not a game feature**: it plays the Wizard just badly enough that one person can run the Builder-side loop (change something, watch deliveries / spawns / XP happen) without a second human. Code: `js/devbot.js`, tuning: `CFG.devBot` (config.js; tick, retreat HP, kite band, engage / roll / seek / forage radii, strafe + wander timing, idle / stuck limits).

- **Toggle**: F4 while the F3 overlay is open, or `__wands.bot('wizard')` / `__wands.bot(null)`. Default off on every load, never saved, switched off by `Main.toTitle`. Not in menus or settings (it is listed only in the Controls page's DEBUG section). While on: a `BOT: WIZARD` chip under the Wizard's goal card and two lines in the F3 overlay (mode, deaths, **time to first death**, per-life times, bot XP / kills). Stats reset when the bot is switched on or a new game starts; a death counts only if it happens while the bot is driving.
- **Real input path (hard rule)**: each frame, after `IN.pollPads()`, `DevBot.drive(dt)` writes a gamepad-shaped state into the Wizard's pad slot (stick `ix, iy`, button `a` = roll / dig). The slot is `G.ctl.pw` from the menu world / character select; when the Wizard is on the keyboard (`pw` -1) `DevBot.plug` claims a free slot as the Wizard's pad and `DevBot.unplug` gives `G.ctl.pw` back when the bot is switched off. `Main.controls` and `WZ.update` consume it exactly like a human's, so water slide, bog slow, roll i-frames, roll buffering and forage mashing are the real ones. The bot only *reads* game state to decide (`G.w.enemies / drops / pickups`, `WZ.forage / harv`, `WZ.blocked` for steering); it must never call anything that moves, rolls, digs or picks up. Setup cheats in tests may use the normal `__wands` hooks. Don't add tuning-style cheats (extra HP, free rolls) to it.
- **Safe**: the pad state is neutral while paused, dead, in a grace beat or with either skill tree open (it never presses the tree buttons, so `Main.treePads` cannot buy anything). A real second gamepad is overridden while it is on.
- **Behaviour** (a decision every `tick` = 0.15s, held in between): survive (HP < 35%: take a reachable potion / armor, else run from the foe centroid; roll when a foe is within `rollR` and the real cooldown allows, `rollChance` of the time) > collect (gems, then resources, then shards / Cores, within `seekR`, not while a foe is within `collectEnemyR`; potions / armor when hurt) > hold a bandMin..bandMax band from the nearest foe within `engageR`, strafing in on / off bursts > forage spots (stand still, press roll every `mashGap`), resource nodes (stand `harvestDwell` s) > wander to the least-visited nearby cell (leash `wanderLeash` from spawn). Idle > `idleMax` s forces a wander; pushing but moving < `stuckMove` tiles in `stuckT` s sidesteps for `stuckBack` s (twice in a row also drops the goal). Spots it gave up on are ignored for `skipT` s.
- **Deliberately mediocre**: no boss / elite logic, no tree, no goal-chasing, no pathfinding beyond look-ahead steering + the real slide. Its deaths are the measurement; if it exposes a balance problem, report it, don't tune the game around the bot.
- Soak recipe (headless): `start(1)`, `bot('wizard')`, then loop `deliver(kind)` / `egg(kind)` + `step(0.05, 20)`, `event(n)` / `boss()` for pressure, click `#rRe` after a death; read `DevBot.info()` (`firstDeath`, `deaths`, `lifetimes`).

## Conventions

- Every tuning number goes in `CFG` (config.js). New items → `ITEMS`; recipes → `CFG.recipes` (+ a tree node if gated); buildings → `CFG.buildings` + sprite `b_<type>` + hotbar entry; tree nodes → `CFG.tree`.
- New sprites: procedural in sprites.js inside `task(() => …)`; anchor bottom-centre unless noted; building sprites 20×34 with the base diamond centred at (10,26). New UI icons: add a pixel map with `icon('name', rows)` → `ic_name`.
- New interactions belong in `FA.actionFor` / `FA.bldAction` so the prompt bubble stays truthful.
- Toasts: `UI.toast(text, 'L'|'R', iconKey)` — plain ASCII text, icon as a sprite key.
- Use `UI.changed()` after state changes that should trigger a prompt autosave.
- Keep strings ASCII (the pixel fonts lack most symbols/emoji).
- **Digits**: every digit in the game (DOM and canvas) comes from Silkscreen through the digits-only `Digits` (display stack, `size-adjust: 150%`) and `DigitsB` (body stack) faces at the front of `--display` / `--body` and `FONT_D` / `FONT_B`. The old body font (Pixelify Sans) drew 3/5/6/8 alike and Press Start 2P's 6 turns into a G when the stage scales down, so never put a font in front of them. New font stacks must start with the digit face too.
- New tunable numbers go in `CFG` so the Variables tab picks them up automatically (it walks every numeric leaf; arrays of objects with an `id` are addressed by `#id`).
- Match the existing style: compact functions, short comments only where intent isn't obvious, no frameworks.

## Ideas / known gaps

- The creature / event / Stronghold numbers (HP, damage, gem chances, Warden strength, event sizes, the 12 creature cap) are first guesses and were tested headlessly only (every creature's behaviour, every event, a Stronghold claim, saves, the tree totals); nobody has played them yet.
- Crafted elites (5%) follow the elite rules as asked, so they drop a Shard: cheap Wisps can farm Shards slowly (about 1 per 20 Eggs, plus the bonus-shard pity). `CFG.crafted.eliteShards = false` turns that off.
- Event foes use the normal flow-field chase; a Migration is a line of foes spawned across one direction, not a scripted march.

- Boss, elites, biome foes, landmarks, shards and logistics were added in one pass and tested headlessly only; boss HP (4200), elite odds, shard amounts and landmark rewards are first guesses.
- Balance of the 12× longer progression hasn't been playtested by humans yet (the F3 debug overlay is there to measure it).
- The goal chain doesn't explain the Splitter filter's role in the boss fight; a toast when the boss's weakness changes is the only nudge.
- The flow field covers a 97×97 window; monsters outside it (they teleport closer past 45 tiles anyway) fall back to straight lines.
- A Wizard request/ping button and accessibility options (remapping, colourblind glyphs, shake toggle) are still open ideas.
- Real two-player play with two gamepads hasn't been tested in-session; only headless tests and screenshots.
